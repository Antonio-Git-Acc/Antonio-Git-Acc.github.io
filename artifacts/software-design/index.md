# Software Design and Engineering Enhancement

**Artifact:** 3D Scene Project
**Original course:** CS 330 – Computational Graphics and Visualization

The artifact I have chosen for the software design and engineering category is a 2D interactive physics simulation that I had created prior in my CS 330 class. Originally developed as a C++ application using OpenGL and the GLFW library, the project simulates circles bouncing off reflective bricks, damaging and destroying destructible bricks, and merging with other circles upon collision. It represents my first major foray into graphics programming and physics simulation. The original application featured a grid of colored bricks, the ability to spawn circles by pressing the space bar, collision detection using closest-point calculation, and basic circle-merging mechanics. While functional, the code is a bit monolithic, lacked formal architecture, and contained many magic numbers and unused variables. 

The reason I chose this artifact was because it works to demonstrate my foundational skills in software design and engineering, including object-oriented programming, collision detection algorithms, and interactive user input handling. The original code showcased my ability to implement complex physics logic and offered many opportunities for architectural improvement which makes it ideal for the enhancement. 

For the artifact, I addressed a number of issues I noted during my code review. All of the code being in a single file was drastically improved by making a modular architecture with a GameObject base class and derived Brick and Circle classes. A GameWOrld class now encapsulates the whole game state and separate Renderer and InputHandler classes help keep those roles better managed. All of this separation helps dramatically with maintainability and testability. The magic number constats and well were replaced with named constants in the GameConstats header file to make tuning parameters easier. The programming was also improved with bounds checking and null checks, like in the collision detection. Documentation was also an issue that needed addressing so I made sure to have comments on every class and method to explain their purpose, parameters, and return values. Lastly, unused variables like the speed variable in the Circle class were taken out. With all of these enhancements, I feel that I’ve done a sufficient job in demonstrating my ability to take a functional but subpar codebase and transform it into something much more structured, maintainable, and extensible in a way that follows the industry’s best practices. 

As for course outcomes, I feel that I met the ones I planned to do so for this. Course outcome 3 is about designing and evaluating computing solutions which I’ve achieved with the architectural refactoring and collision detection improvements that follow object-oriented principles. Course outcome 4 is for using well-founded and innovative techniques which was done through base class inheritance, separation of concerns, and using industry-standard tools like CMake for build configuration. Lastly course outcome 1 is partially met through the merit of making the codebase have a more modular architecture and be better documented which goes a long way in making it easier for other developers. 

The enhancement process was challenging and rewarding. Making pseudocode for what I planned to do helped in visualizing the refactoring. Refactoring in general seemed more difficult for me than it would be to make entirely new code as I had to make sure that the original functionality was preserved as it was while simultaneously improving the structure. The most significant challenge was to ensure that the scene graph architecture didn’t have any performance regressions, requiring testing with the original and the new codebase just to be certain that nothing was negatively impacted. Additionally, balancing the clean architecture with the constraints of OpenGL was a bit difficult. Overall, this enhancement did well in reinforcing my belief that good software design is iterative. The original code worked but the enhanced version does just as well while also being much, much easier to maintain and extend in the future.
